# drivecast 产品与内容体系设计

> 定位:面向资深后端工程师的**通勤面试学习播客生成器**。用户给主题,AI 拆学习计划、逐集写面试导向脚本、edge-tts 合成中文音频,路上听,听完自测,形成复习闭环。
> 本文档是内容侧的权威契约:数据结构、脚本模板、题库结构、复习机制。后续生成管线(LLM prompt、存储 schema)以此为准。

---

## 1. 产品定位与核心用户流程

### 1.1 定位一句话

把"通勤的 40 分钟"变成"面试准备的高效输入时间"——不是泛科普播客,而是**结构化的面试陪练音频**:每集都有知识点、有真题问法、有答题话术、有易错点,听完能直接拿去答面试官。

### 1.2 与泛技术播客的差异(设计红线)

| 维度 | 泛技术播客 | drivecast |
|---|---|---|
| 目标 | 了解/开阔眼界 | 通过面试 |
| 深度 | 入门科普 | 匹配资深工程师(有 Go 微服务/多租户 SaaS 实战) |
| 结构 | 自由漫谈 | 固定五段:知识点→问法→话术→易错→自测 |
| 听完后 | 结束 | 留 3 个自测问题,下集开头回顾,进题库复习 |

**红线:禁止"什么是 XX,它很好用"式水稿。** 每个知识点默认听众已经会用,要讲的是原理、权衡、坑和面试怎么答。

### 1.3 核心用户流程(闭环)

```
输入主题/方向
   │
   ▼
[1] 生成学习计划(Plan):AI 把主题拆成 N 集,每集 10-20 分钟(=单程通勤)
   │        用户可增删/调整集,确认后锁定
   ▼
[2] 逐集生成脚本(Script):按内容方向选模板(独白/对话),LLM 写稿
   │        每集含:核心知识点 + 高频面试问法 + 答题框架 + 易错点 + 3 个自测问题
   ▼
[3] edge-tts 合成音频(Episode audio):中文语音,本地存 mp3
   │
   ▼
[4] 路上收听(浏览器播放器):支持倍速/进度记忆/单集循环
   │
   ▼
[5] 复习闭环(Review):
     · 每集结尾播 3 个自测问题(留空白让用户心里作答)
     · 下一集开头先"回顾上集 3 问并给参考答案要点"
     · 自测问题自动入面试题库,供到公司后对着答案框架自评
   │
   ▼
面试前:按知识点维度刷题库 + 重听薄弱集
```

### 1.4 关键使用场景

- **周日晚上**:输入"分布式一致性"和"RAG 工程",生成两周的通勤计划(每天来回 2 集)。
- **工作日早上**:打开浏览器,自动续播昨晚队列,路上听 1-2 集。
- **到公司/午休**:打开题库,对着早上那集的 3 个自测问题默答,看参考框架,标记"掌握/模糊/不会"。
- **面试前 3 天**:按"模糊/不会"过滤题库,重听对应集。

## 2. 学习计划数据结构(主题 → N 集)

### 2.1 拆集原则

- **一集 = 一个可被 10-20 分钟讲透的知识单元**,且能在面试中独立成问。太大(如"整个分布式")必须拆,太小(单个命令)合并进上级主题。
- **递进关系**:同一主题内,集按"原理 → 实现 → 权衡/对比 → 实战/排障 → 系统设计串联"递进。前几集铺概念地基,后几集考综合与权衡(这是资深岗的区分度所在)。
- **集时长**:`target_minutes` 默认 15(可 10/15/20/30/40),由脚本字数反推。中文 TTS 实测语速约 **280-320 字/分钟**(rate=-5% 车载基调下,见 03 §6.1),15 分钟 ≈ **4500 字**正文,40 分钟 ≈ **12000 字**。换算系数存配置,合成后用 ffprobe 真实时长回填校准。

### 2.2 Plan / Episode 数据结构

```jsonc
// Plan 学习计划
{
  "plan_id": "plan_20260820_01",
  "title": "分布式一致性与共识",
  "direction": "backend_arch",        // 四大方向之一,见 §3
  "user_topic": "分布式一致性 / Raft / 分布式锁",  // 用户原始输入
  "level": "senior",                  // 深度档位,默认 senior
  "total_episodes": 6,
  "status": "active",                 // draft | active | done | archived
  "created_at": "2026-08-20",
  "episodes": [ /* Episode 摘要,按 seq 有序 */ ]
}

// Episode 单集
{
  "episode_id": "ep_plan01_03",
  "plan_id": "plan_20260820_01",
  "seq": 3,                            // 集序,递进关系的载体
  "title": "Raft 共识:选主、日志复制与安全性",
  "goal": "能讲清 Raft 三大子问题,答出与 Paxos 对比、脑裂如何处理",
  "depends_on": ["ep_plan01_01", "ep_plan01_02"],  // 前置集(递进依赖)
  "target_minutes": 15,
  "script_format": "monologue",        // monologue | dialogue,见 §3
  "knowledge_points": [                // 本集覆盖的知识点,挂题库
    "kp_raft_leader_election",
    "kp_raft_log_replication",
    "kp_raft_safety_commit_rule"
  ],
  "script": {
    "status": "ready",                   // 生产状态机: pending | scripted | tts_ready | synth_partial | ready | failed
    "text_path": "scripts/ep_plan01_03.md",   // 正文权威存 DB script 表,此处为过程态导出
    "audio_path": "audio/episodes/ep_plan01_03.mp3",
    "actual_seconds": 912
  },
  "recap_of_previous": [               // 开头回顾:来自上一集的 3 个自测问题 id
    "q_xxx1", "q_xxx2", "q_xxx3"
  ],
  "self_test_question_ids": [          // 结尾自测:本集产出的 3 题,入题库
    "q_yyy1", "q_yyy2", "q_yyy3"
  ],
  "listen": {
    "status": "done",                  // unlistened | listening | done
    "progress_sec": 912,
    "listened_at": "2026-08-21"
  }
}
```

### 2.3 递进关系示例(6 集的"分布式一致性"计划)

| seq | 集 | 角色 | 递进 |
|---|---|---|---|
| 1 | 一致性模型谱系:线性一致 / 顺序一致 / 最终一致 | 地基 | 建立术语与判断标准 |
| 2 | CAP 与 BASE:到底在权衡什么(破除"三选二"误解) | 地基 | 纠正常见错误认知 |
| 3 | Raft:选主、日志复制、安全性 | 核心原理 | 依赖 1 的术语 |
| 4 | Raft 工程细节与脑裂、成员变更、快照 | 实现/坑 | 依赖 3 |
| 5 | 分布式锁与一致性的关系:Redlock 争议、 fencing token | 权衡/实战 | 依赖 2/3 |
| 6 | 系统设计串联:设计一个强一致配置中心 | 综合 | 串起 1-5,模拟面试 |

第 1 集无 `recap_of_previous`;第 N 集开头回顾第 N-1 集的自测题。允许跨主题依赖(如"RAG 检索"依赖"向量索引"知识点),但默认只在同 plan 内强递进。

## 3. 四大内容方向的播客脚本模板

### 3.1 选独白还是对话?

- **独白式(单人讲师)**:信息密度高、节奏可控、TTS 单音色最稳,适合原理深读、八股精讲。**默认。**
- **双人对话式(主持人+专家)**:主持人扮演"面试官/小白追问者",负责追问、抬杠、要举例;专家负责给框架。更耐听、更易代入面试场景,适合面试问法密集、需要"你问我答"的方向。

约定:①④以独白为主,②③以对话为主(资讯类对话更不易枯燥);用户可在生成计划时逐集覆盖。对话式 TTS 用两个 edge-tts 音色区分角色。

### 3.2 通用五段结构(所有方向共用,时长按 15 分钟基准等比缩放)

| 段 | 时长 | 内容 | 面试导向作用 |
|---|---|---|---|
| S0 回顾 | ~1min | 回顾上集 3 个自测问题并给参考要点(第 1 集跳过) | 间隔重复 |
| S1 核心知识点 | ~5min | 讲透原理:是什么、为什么这样设计、关键机制 | 答"原理题"的底子 |
| S2 高频面试问法 | ~4min | 2-3 个真实面试问法,由浅到深/连环追问 | 提前见题 |
| S3 答题框架/话术 | ~3min | 每个问法给一个可复用的答题骨架 + 示范话术 | 直接可用 |
| S4 易错点+自测 | ~2min | 资深者也常答错的 1-2 个坑;留 3 个自测问题 | 避坑 + 留钩子 |
| S5 参考资料 | 片尾 ~30s | 参考文献口播:只念资料标题,URL 留在文稿末尾点击(见 03 §2) | 溯源读原文 |

长集(30/40 分钟)按 1/5/4/3/2 占比等比放大各段字数;单段超过单 agent 字数上限(`section_max_words_per_agent`,默认 2400 字)时,该段再拆成多个并行子 agent 分片写作后拼接(S1 按知识点切片、S2 按题库问法切片、S3 按问法顺序均分),单次 LLM 调用字数始终受控。

**答题框架统一要求**:每个框架给"总—分—钩"结构:先一句话结论/分层,再 2-3 个要点,最后留一个"追问钩子"(主动抛更深的点引导面试官,掌握主动权)。这是资深岗加分手法,必须在脚本里体现。

### 3.3 方向一:后端/架构面试(`backend_arch`)—— 独白为主

- **选材**:Go  runtime/调度/GC、分布式、MySQL/索引/事务、Redis、Kafka/RocketMQ、系统设计八股(短链/秒杀/feed/IM)。
- **模板侧重**:S2/S3 占比最高(面试问法密集)。S1 只讲到"能支撑答题"的深度,不做源码级展开(源码留给方向四)。
- **每集必备**:"连环追问链"——模拟面试官就一题连问 3 层(概念 → 为什么 → 极端场景怎么办),示范如何逐层接住。
- **示例集**:《Go map 的扩容与并发安全》《MySQL 索引下推与最左前缀的连环追问》《设计秒杀:从扣减到限流的取舍》。

### 3.4 方向二:AI/LLM 工程(`ai_llm`)—— 对话为主

- **选材**:RAG(切块/检索/重排/评估)、Agent(ReAct/工具调用/规划)、微调(SFT/LoRA/DPO)、推理优化(KV cache/量化/批处理/vLLM)。
- **模板侧重**:S1 讲清"工程权衡"(不是论文科普),S2 聚焦"你会怎么落地/怎么评估/线上出了 X 问题怎么排查"这类工程面试题。
- **每集必备**:"落地决策点"——把抽象方案落到选择(如 chunk 怎么切、rerank 要不要上、幻觉怎么评估),给出判断依据。资深岗考的是权衡不是名词。
- **示例集**:《RAG 检索质量上不去,从哪几个环节排查》《Agent 工具调用的可靠性与兜底》《KV cache 与连续批处理为什么能提吞吐》。

### 3.5 方向三:前沿技术资讯(`tech_news`)—— 对话为主

- **选材**:近 1-2 周 LLM/云原生/infra 领域值得工程师关注的新发布、新论文、新工具。
- **模板侧重**:结构改为"发生了什么 → 为什么重要 → 对工程师/面试的影响"。资讯本身不是考点,**要能落到"如果面试官问起你怎么看 XX,你怎么答"**。
- **每集必备**:"观点话术"——给一个有条理的看法模板(事实 → 影响 → 我的判断 → 待观察),避免被问到时只会"挺厉害的"。
- **注意**:此方向不强行进题库,只把"可能成为面试话题"的点抽成问答题入库;时效性强,计划不宜排太远。

### 3.6 方向四:源码/原理深读(`source_dive`)—— 独白为主

- **选材**:Go runtime、etcd/Raft 实现、Redis 数据结构、Linux/网络核心机制、LLM 推理框架关键路径。
- **模板侧重**:S1 占比最高(讲机制与代码路径),但**全程带着面试问题讲**——"这段源码对应面试里哪道题""面试官想听到你讲出哪个点"。
- **每集必备**:"源码→面试映射"——明确说出"看到 X 实现,面试被问 Y 时你可以引用 Z 细节加分"。深读不是目的,能在面试里引用才是。
- **示例集**:《GMP 调度:从源码看 work-stealing,面试怎么讲》《etcd 如何用 Raft 保证线性一致读》。

### 3.7 脚本文本规范(喂给 TTS 前)

- 纯口播文本,不含 markdown/代码块/表情;代码标识符读作自然语言(`sync.Mutex`→"sync 包的 Mutex")。
- 对话式用固定角色前缀(`主持人:`/`专家:`),TTS 按前缀切音色。
- 段间用停顿标记(如 `。。` 或空行)控制节奏;数字、英文术语用中文读法或慢读处理。
- 结尾自测问题后留 2-3 秒空白,给用户心里作答时间。

## 4. 面试题库数据结构(听后复习)

题库与计划解耦:题目挂**知识点**,知识点再关联播客集。这样同一知识点可被多集覆盖,复习时按知识点聚合,而非按集。

```jsonc
// KnowledgePoint 知识点(题库的索引维度)
{
  "kp_id": "kp_raft_leader_election",
  "name": "Raft 选主机制",
  "direction": "backend_arch",
  "tags": ["分布式", "共识", "Raft"],
  "related_episodes": ["ep_plan01_03", "ep_plan01_04"]  // 覆盖此点的集
}

// Question 面试题
{
  "q_id": "q_raft_001",
  "kp_id": "kp_raft_leader_election",
  "source_episode": "ep_plan01_03",     // 来自哪集的自测/讲解
  "question": "Raft 选主时,如果两个候选者同时拿到相同票数会怎样?如何避免长期选不出主?",
  "difficulty": "medium",               // easy | medium | hard
  "answer_framework": {                 // 答题框架,不是长篇答案,是可复述的骨架
    "conclusion": "随机超时 + 任期递增保证最终选主",
    "points": [
      "同票则本轮无主,各自等待随机 election timeout 后进入下一 term 重新发起",
      "随机超时使冲突概率随重试指数下降,避免活锁",
      "任期(term)单调递增,过期 leader 被新 term 拒绝"
    ],
    "follow_up_hook": "主动补:实际工程里 timeout 取值(如 etcd 心跳 100ms/超时 1s)与网络分区恢复"
  },
  "common_mistakes": "只说'重新选'而讲不出随机超时如何避免反复同票(活锁)",
  "review": {                            // 复习状态,驱动 §5 闭环
    "mastery": "fuzzy",                  // unknown | fuzzy | mastered
    "self_test_count": 2,
    "last_reviewed": "2026-08-21",
    "next_review": "2026-08-23"          // 间隔重复,见 §5.3
  }
}
```

**查询视角**:
- 按知识点刷题(面试前主攻某领域)
- 按 `mastery != mastered` 过滤(只复习不会的)
- 按 `next_review <= today`(今日到期)
- 从题反查 `source_episode` 重听对应集(`related_episodes` 给重听入口)

## 5. 复习闭环设计

### 5.1 三级复习机制

1. **即时自测(听中)**:每集结尾播 3 个自测问题,问题后留空白。用户路上心里作答,这 3 题即 `self_test_question_ids`,自动入题库,初始 `mastery=unknown`。
2. **次日回顾(间隔)**:下一集开头 S0 段,先重述上集 3 问并给**参考答案要点**。利用通勤的天然每日间隔做一次主动回忆 + 对答案,这是记忆最划算的一次重复。
3. **到站自评(主动)**:到公司后翻题库,对这 3 题标 `掌握/模糊/不会`。标记驱动后续重听与间隔重复。

### 5.2 自测问题设计规范

- 每集恰好 3 题:**1 题考概念记忆**(S1 内容)、**1 题考面试问法**(S2 原题)、**1 题考应用/权衡**(把知识点放进一个新场景)。
- 问题必须**可用一句话问出、可在脑中组织答案**(口播场景,不出选择题/计算题)。
- 问题的 `answer_framework` 就是 S3 答题框架的浓缩,保证"听到的框架 = 复习时的框架"。

### 5.3 间隔重复与重听策略(轻量,不上完整 Anki)

- `mastery` 三态流转:`unknown → fuzzy → mastered`,自评时更新;答错/标"不会"回退 `unknown`。
- `next_review` 简化间隔:`fuzzy=+2 天`,`unknown=+1 天`,`mastered=+7 天`(再对则不再主动推)。
- **重听联动**:某知识点下 `fuzzy/unknown` 题 ≥2 时,在其 `related_episodes` 里推荐重听最短的那集,并入次日播放队列。
- **面试冲刺模式**:用户设"面试日"后,系统把 `mastery != mastered` 的题按 direction 聚合,生成一个"考前 3 天重听清单"(优先重听题多的集)。

### 5.4 闭环度量(给用户反馈,形成正循环)

- 每 plan 显示:`已听集数/总集数`、`题库掌握率(mastered/总题数)`、`待复习题数`。
- 通勤连续性:连续 N 天有收听记录给轻量提示(不做游戏化,一个 streak 数字即可)。
